# 本机工作流接入现状与验收标准

更新时间：2026-07-19

## 一、当前结论

项目按“单人、本机、自用”运行。十个已下载模型对应的工作流已经制作为项目自己的不可变内容包，并绑定到三个明确的本机推理后端：

| 后端编号 | 固定地址 | 用途 |
| --- | --- | --- |
| `comfy-visual-8000` | `http://127.0.0.1:8000` | 图片、图片编辑、视频 |
| `comfy-index-8001` | `http://127.0.0.1:8001` | IndexTTS2 语音 |
| `comfy-omni-8002` | `http://127.0.0.1:8002` | OmniVoice 语音 |

前端选择的是“生成配置修订编号”，不是模糊的模型名称。任务创建后会把该编号、工作流摘要和后端编号写入不可变执行快照。某个配置失败时，系统必须失败，不得切换到其他配置。

## 二、个人本机启用与正式发布彻底分开

个人本机启用记录的类型是 `local-self-use`，正式发布验证记录的类型是 `release`。两者可以同时存在，但不能互相覆盖或互相冒充。

个人本机记录只有同时满足以下三项时才有效：

1. `AI_M_LOCAL_SELF_USE=true`；
2. `AI_M_USER_IDENTITY_MODE=single-user`；
3. `AI_M_SINGLE_USER_ID` 是有效的固定用户编号。

任意一项关闭后，个人本机记录立即不再参与模型列表、任务创建和任务执行。正式发布仍然只接受正式发布记录以及激活状态，不受个人模式影响。

## 三、启用命令

先按本机实际目录配置模型根目录。三个后端模型目录不同时，使用后端到目录的明确映射。

```powershell
$env:AI_M_LOCAL_SELF_USE='true'
$env:AI_M_USER_IDENTITY_MODE='single-user'
$env:AI_M_SINGLE_USER_ID='local-user'
$env:AI_M_LOCAL_SELF_USE_MODELS_ROOTS_JSON='{"comfy-visual-8000":"<视觉模型目录>","comfy-index-8001":"<IndexTTS2模型目录>","comfy-omni-8002":"<OmniVoice模型目录>"}'
corepack pnpm workflow:enable:local-self-use
```

该命令会在一次数据库事务前完成以下检查：

1. 后端地址只能是本机回环地址；
2. 后端编号必须在明确允许列表中；
3. 每个配置只选择最新修订，旧修订同时禁用；
4. 工作流内容摘要必须匹配；
5. 必需节点必须由对应后端真实公布；
6. 运行时模型名称必须精确匹配；
7. 模型文件大小和内容摘要必须匹配；
8. 探测期间数据库状态若被并发修改，整批启用失败；
9. 所有检查通过后，三个后端和所选配置才在一个事务中启用；
10. 不写入或修改正式审批人、正式审批时间和正式审批报告。

## 五、解耦边界

项目运行时不得读取 `D:\demo1\Pixelle\Pixelle\workflows\selfhost`。该目录只作为一次性导入来源。

必须复制并固化到项目控制的内容包括：

- 工作流；
- 清单；
- 参数绑定；
- 包锁文件；
- 必需自定义节点或独立运行环境。

允许共享只读模型仓库，但每个模型必须用文件大小和内容摘要锁定。目录链接、符号链接、回到原工作流目录的绝对路径和运行时引用均禁止。

## 六、完整验收标准

### 6.1 启用与隔离

- 十个配置全部存在且各自只启用最新修订。
- 三个后端全部是明确的回环地址。
- 个人记录与正式记录可同时存在，任何一方更新不得覆盖另一方。
- 关闭个人模式后，只有个人记录的配置从列表消失且不能创建新任务。
- 个人启用不得改变正式审批人、审批时间和审批报告。

### 6.2 模型与工作流完整性

- 每个工作流内容摘要与导入记录一致。
- 每个必需节点在对应后端真实存在。
- 每个模型的运行时名称、物理文件大小和内容摘要全部匹配。
- 任意模型改动一个字节、替换文件、缺失文件或经目录链接逃逸，启用必须失败。
- 运行时选项零匹配、多匹配或空列表时必须失败，自由文本输入保持原值。

### 6.3 前端选择与精确路由

- 手工配置与数据库工作流配置同时显示，互不遮蔽。
- 相同配置修订只显示一次，数据库记录优先。
- 未明确选择时不得自动选择第一项。
- 配置列表读取失败时保留原选择并提示错误，不得切换模型。
- 选择 IndexTTS2 时，任务快照只能绑定 `comfy-index-8001`。
- 选择 OmniVoice 时，任务快照只能绑定 `comfy-omni-8002`。
- 选择图片或视频配置时，任务快照只能绑定 `comfy-visual-8000`。
- 后端失败、模型缺失或环境漂移时，任务明确失败，不得回退其他本地或在线模型。

### 6.4 安全与并发

- 无浏览器来源的普通写请求必须拒绝；受信代理和带强令牌的本机客户端除外。
- 本机客户端令牌必须使用定时安全比较，弱令牌拒绝。
- 上传实际字节不得超过声明字节；少报大小必须在流式写入阶段失败并释放配额。
- 并发上传的已用空间与预留空间总和不得突破项目配额。
- 探测后、事务写入前发生配置变化时，整批启用回滚。
- 任务输入默认保留三十天供失败任务重试；终态任务到期后释放输入快照和源素材引用。
- 输入已经释放或超过保留期限的旧任务不得原地重试，必须用当前仍有效的输入创建新任务。

### 6.5 数据库与提交

- 从空数据库、旧版本数据库和当前数据库升级全部通过。
- 迁移后旧个人记录正确标记为个人类型，旧正式记录标记为正式类型。
- 验证类型、工作流摘要和后端编号组合必须唯一。
- 数据库、模型、日志、上传文件、生成产物和机器专用路径不得进入提交。
- 类型检查、代码规范检查、全部测试、迁移测试、构建和差异空白检查全部通过。

## 七、当前不再作为个人使用前置条件的事项

以下事项属于多人或正式发布治理，不再阻止个人本机使用：

- 两个操作系统账户分别审批；
- 三个服务使用专用低权限账户；
- 双人正式发布审批；
- 把完整故障演练作为首次本机启用前置条件。

这些要求被取消后，功能约束并未取消：精确选择、精确路由、禁止回退、模型字节校验、回环地址限制、不可变任务快照和失败关闭仍然必须保留。
