## 1. 统一执行规则

每个场景必须保存命令、固定代码摘要、开始和结束时间、注入点、数据库前后快照、资源槽与领取租约、临时目录、进程、端口、后端流量计数、结果和恢复后的正常任务证据。

- 普通失败场景连续执行三次，三次结果必须一致。
- 并发场景执行二十轮，重复推理、双释放、负容量和重复工件必须均为零。
- 超时场景实测不超过配置期限加百分之二十调度余量。
- 每组故障结束后执行一次正常应用任务；只有正常任务成功且资源无残留，才能证明恢复有效。
- 直接验证器、假后端或单元测试只能作为前置证据，不能替代要求真实应用进程、真实数据库或真实 8000 后端的场景。

### 1.1 待实现的统一执行器契约

目前尚无满足安全要求的真实故障执行器，因此以下命令是剩余开发接口，不是已经可用的命令。实现完成前禁止操作者用手工删除、改名、杀进程或填满真实磁盘的方式冒充验收。

```powershell
corepack pnpm fault:prepare -- --source-db <只读数据库副本来源> --sandbox-root <全新隔离目录> --backend-url http://127.0.0.1:8000 --generation-digest <最终候选代际>
corepack pnpm fault:run -- --case FI-01 --rounds 3 --sandbox-root <隔离目录> --evidence-root <隔离证据目录>
corepack pnpm fault:run -- --case FI-14 --rounds 20 --sandbox-root <隔离目录> --evidence-root <隔离证据目录>
corepack pnpm fault:assert-clean -- --sandbox-root <隔离目录> --evidence-root <隔离证据目录>
corepack pnpm fault:recover -- --sandbox-root <隔离目录> --normal-job <受控正常任务参数>
```

执行器必须满足：

1. `fault:prepare` 只接受显式创建的隔离目录和数据库副本；解析后的路径若位于项目真实上传、真实数据库、工作流供应链、模型根或用户目录内，立即拒绝。
2. `fault:run` 的 `--case` 只接受 FI-01～FI-18 固定枚举；每项注入点编译进执行器，不接受任意命令、脚本路径、进程标识、环境变量名或文件路径。
3. 进程终止只允许作用于由本次 `fault:prepare` 启动并记录了创建时间、启动令牌和命令摘要的子进程；仅凭进程号不得终止。
4. 文件故障只允许作用于本次隔离目录中的一次性卷；磁盘满使用有上限的虚拟磁盘或配额卷，禁止写满宿主真实卷。
5. 每轮自动采集任务、尝试、资源槽、领取租约、防旧写令牌、外部身份、工件摘要、监听器、进程创建身份和后端请求计数；缺一字段即判失败。
6. 每个普通场景必须由执行器强制三轮，并发场景强制二十轮；命令行不能降低轮次。开发调试可使用单轮，但输出必须标为 `NON_ACCEPTANCE` 且不能进入最终证据目录。
7. 每轮结束自动运行 `fault:assert-clean`；失败时停止后续轮次并保留现场。只有清理断言通过后，`fault:recover` 才能执行正常任务。
8. 证据目录采用内容摘要和原子提交协议；在 Windows 目录耐久协议未解决前只能生成 `BLOCKED_EVIDENCE`，禁止生成通过结论。
9. 每个场景实现时必须在本矩阵补充实际注入开关、目标阶段、预期数据库状态、恢复动作和执行器测试路径；不得只把概念描述改成“已完成”。

### 1.2 场景到执行器注入点的强制映射

| 场景 | 固定注入点 | 恢复动作 |
| --- | --- | --- |
| FI-01 | 请求规范化入口 | 无状态清理，执行正常任务 |
| FI-02 | 最终候选模型清单读取或节点盘点 | 恢复只读模型映射，重新盘点 |
| FI-03 | 隔离包副本校验前单字节篡改 | 丢弃隔离副本，从只读源重建 |
| FI-04 | 传输连接建立后、请求体首字节前 | 按确定未提交策略重试 |
| FI-05 | 请求体末字节后、响应头前 | 对账外部身份，禁止直接重试 |
| FI-06 | 执行中取消与完成屏障 | 以已提交工件和终态证据结算 |
| FI-07 | 共享后端全局中断分支 | 拒绝中断，等待或隔离处理 |
| FI-08 | 输出流写入部分文件后 | 删除部分文件，只重试收集 |
| FI-09 | 文件同步、改名、目录同步三阶段 | 重放提交协议，拒绝半提交 |
| FI-10 | 已提交后端任务、未终态时终止受控后端 | 重启、对账、禁止猜测成功 |
| FI-11 | 受管停止和启动子命令返回非零 | 保持停止领取，人工解除 |
| FI-12 | 新进程存在但健康探测永不就绪 | 终止本次受控子进程 |
| FI-13 | 领取、提交、对账、下载、工件提交、释放六阶段终止工作进程 | 重启工作进程并按阶段恢复 |
| FI-14 | 两个独立恢复扫描器同窗读取 | 由租约与防旧写令牌裁决 |
| FI-15 | 有界配额卷耗尽与两个配额预留并发 | 释放预留、清除部分文件 |
| FI-16 | 下载流返回超大、截断、伪类型三种媒体 | 删除部分文件并拒绝发布 |
| FI-17 | 非回环、重定向、解析变化、实时连接四条路径 | 关闭连接并保持任务未提交 |
| FI-18 | 空闲和活动任务两种关闭屏障 | 有界排空或保留可恢复租约 |
