## 3. 解耦边界

准备阶段只读取原工作流一次，并把以下内容写入项目自己的内容寻址代际：

- 标准化后的接口工作流；

- 模型物理目录、运行时分类、文件名、大小和内容指纹；

运行任务时只使用数据库中已发布的内容包和生成配置。原目录被删除、移动或修改，不应影响已经发布的代际。

模型大文件可以共用只读模型根目录，但工作流内容、数据库、输入、输出、用户目录、日志和运行时目录不得引用原项目目录。共用模型文件不等于共用执行环境。

## 4. 前端选择的因果链

前端选择项保存的是“生成配置修订编号”，不是模型显示名称。完整链路为：

`前端选择项 → 生成配置修订 → 工作流内容摘要 → 执行后端编号 → 固定本地地址`

因此：

- 选择 `IndexTTS2` 对应配置，只能进入它绑定的工作流和后端；
- 选择 `OmniVoice` 对应配置，只能进入它绑定的工作流和后端；
- 选择某个图片配置，只能进入该图片工作流；
- 不能在执行时根据名称猜测模型，也不能悄悄回退到另一个配置；
- 被禁用、被撤销、环境漂移或没有验证记录的配置不得出现在普通用户可选列表。

当前前端和任务服务已经支持上述选择链路，但这十个新内容包尚未正式启用，所以不应提前出现在普通用户列表。

4. 图片编辑包的正式验收还需要指定两张受控参考图；语音包需要已授权的受控参考音频。
5. 两个不同操作系统身份的审批尚未完成。两个自动审查代理只能做代码审查，不能伪造操作系统身份审批。
6. 正式验收上传到共享输入目录的受控素材还缺少可证明的成功、失败和中断清理闭环；在补齐随机受管子目录、清理和清理失败阻断标记前，不允许签发证据。

## 7. 完整验收标准

### 7.1 内容与解耦

- 验收一：原工作流目录改名或暂时不可访问后，已发布内容包仍能被加载和执行。
- 验收二：发布内容中不存在指向原目录的绝对路径、符号链接、目录联接或运行时读取。
- 验收三：任一工作流、绑定或模型文件发生一个字节变化，都必须形成新摘要；旧代际保持只读。
- 验收四：新增内容包不会使合法旧代际的字节完整性复核失效。当前正式验收器只接受十包目录，旧六包不能用新版验收器重新签发证据；回滚只能使用它原先已验收的修订。

### 7.2 模型与节点

- 验收五：每个模型的物理目录、运行时分类、文件名、大小和内容指纹全部匹配。
- 验收六：缺少模型、模型漂移、节点缺失、节点输入类型变化时，在提交任务前失败。
- 验收七：量化模型必须通过运行时分类查询验证，不能用磁盘存在代替服务已加载证明。

### 7.3 前端选择与路由

- 验收八：选择任一生成配置后，任务记录中的配置修订编号与选择值完全一致。
- 验收九：执行器使用该修订绑定的唯一后端地址和唯一工作流摘要。
- 验收十：禁用、撤销、未审批或环境漂移的配置不会出现在用户列表，也不能通过直接请求绕过。
- 验收十一：切换两个不同模型后各运行一次，后端提交的工作流摘要必须不同且分别匹配所选配置。
- 验收十二：没有默认配置时明确报错，不允许静默回退到其他本地或在线模型。

### 7.4 输入与输出

- 验收十三：语音包缺少参考音频时拒绝排队；图片编辑包少于或多于两张参考图时拒绝排队。
- 验收十四：参考素材必须属于当前用户和项目，内容类型、大小、摘要和文件身份均通过校验。
- 验收十四补充：受控素材必须以打开文件句柄的方式限额读取，读取前后文件身份一致，并通过完整容器结构、图片尺寸或音频时长验证。
- 验收十五：输出的媒体类型、结构、尺寸或时长、数量、大小和内容指纹符合清单限制。
- 验收十六：下载中断、输出不完整或类型伪装不能被记录为成功。

### 7.5 真实运行、重启与恢复

- 验收十七：十个包分别在其兼容的隔离执行环境中真实生成成品，禁止用模拟结果代替。
- 验收十八：每个包完成后先提交工件，再关闭连接、重启对应后端、重新连接并重复系统和节点探测。
- 验收十九：重启前后进程身份和连接身份必须变化；端口和配置绑定必须保持不变。
- 验收二十：任一包失败时不产生可导入的完整证据集，不导入、不晋级、不启用。
- 验收二十一：崩溃、断电模拟和主机重启后，只能恢复完整闭合的提交，不接受半成品。

### 7.6 审批、发布与回滚

- 验收二十二：导入者不能审批自己的内容；必须由两个不同操作系统身份分别审批。
- 验收二十三：审批必须绑定内容包摘要、执行后端、环境锁和真实运行证据。
- 验收二十四：通过审批后先以禁用状态导入，晋级验证通过后才能启用。
- 验收二十五：撤销后新任务立即禁止使用，但历史任务和工件仍可追溯。
- 验收二十六：回滚只切换到已验收的旧修订，不删除新数据、不覆盖历史证据。

## 8. 发布判定

只有验收一至验收二十六全部通过，两个独立审查都没有未关闭的高、中、低级问题，并且全量质量门禁通过，才能创建本地候选提交。

当前结论：内容包准备和只读双重清点通过；产品运行接入、正式启用与候选提交均不允许。
