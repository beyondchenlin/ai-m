# 第一轮独立对抗审查记录

日期：2026-07-19  
结论：两名独立审查者均判定“不就绪”  
适用范围：剩余工作计划、单端口六包验收、供应链、运维、故障恢复与回滚

## 1. 判定原则

审查只接受可重复事实，不把说明文字、试运行、假后端或直接调用推理接口替代应用任务链证据。任何高优先级问题未关闭时，禁止导入、晋级、发布和创建候选提交。

## 4. 新发现的真实阻断

### 4.1 模型清单伪通过

旧代际的两个 IndexTTS2 包和两个 OmniVoice 包没有声明真实模型依赖，导致盘点模式伪通过。首次运行 `tts-index2` 后端安全失败并报告关键模型缺失。当前已补充静态模型清单，必须在全部模型下载和摘要复核后重新生成六包代际；旧代际禁止导入或晋级。

### 4.2 部署身份未隔离

实际 8000 端口推理进程与应用操作者使用同一个 Windows SID（安全标识符），禁止目录还继承宽泛读取或修改权限，实际基础目录指向共享数据根。因此当前只能证明参数隔离，不能证明访问隔离。

### 4.3 旧版本回滚顺序不兼容

当前旧版本的迁移日志校验会在数据库包含更新迁移时明确拒绝启动。要满足“旧版本真实读取新数据”的验收标准，发布必须拆成两阶段：

1. 先发布不引入新迁移的兼容过渡版本，使它能只读容忍经过批准的未来追加迁移，同时继续拒绝已知前缀篡改、缺口和哈希变化。
2. 完成兼容过渡版本的回滚演练后，再发布包含新迁移与功能的候选版本。

本工作区尚未完成这一两阶段发布，因此回滚验收当前为不通过。

### 4.4 单进程语音依赖约束无解

全部语音模型下载完成并复核后，新六包代际 `5a40f8bb7c4b8a0f437aca2a73c85e532a9c72e5963acc242992ec4d494d9681` 成功生成。真实首包 `tts-index2` 随后在后端执行阶段失败，且验证器按设计停止剩余包、重启后端、保留失败日志，没有生成或提交可导入证据。

根因不是缺模型，而是单一 Python 环境中的约束不可满足：

- IndexTTS2 官方项目严格锁定 `transformers==4.52.1`。
- 当前 IndexTTS2 插件说明推荐 `4.52.1` 或 `4.54.1`，并明确 `>=4.57.1` 不兼容；其依赖文件却错误地只声明无上界的 `>=4.50.0`，导致包管理器检查伪通过。
- OmniVoice 插件及故障排查说明要求 `transformers>=5.3.0`，并警告升级可能破坏其他节点。
- 当前实际环境为 `transformers==5.8.0`，IndexTTS2 插件导入已经移除的 `transformers.generation.beam_constraints` 后失败。

因此简单降级会破坏 OmniVoice，保留新版会破坏 IndexTTS2，继续在同一 Python 解释器内安装两套依赖不可验收。另一个阻断是 IndexTTS2 插件声明 `license = {file = "LICENSE"}`，但仓库与安装副本均缺少该文件；在商业项目中直接复制修改存在不可接受的授权不确定性。

关闭标准：取得明确许可证依据后，选择并批准“许可证完整的兼容替代实现”或“单一公开端点后的隔离执行环境”之一；锁定全部传递依赖，证明六包顺序执行、包间重启、显存回收、取消、超时、故障恢复和回滚均不串扰；重新生成同一六包代际并从零完成全部真实验收。不得通过降级其中一方、隐藏节点加载失败或拆成未经批准的多个公开端口绕过。

### 4.5 Windows 目录提交耐久性未证明

新六包生成记录显示文件同步成功，但目录同步结果为不支持。原子改名只能证明命名空间切换不可分割，不能单独证明目录项已经跨断电持久化；因此当前证据还不满足“提交先持久化，随后才允许重启”的验收语义。第二轮审查进一步发现，验证器原先会吞掉 Windows 的目录同步不支持错误并继续签名，这是伪证据风险；现已改为生产路径默认拒绝，只有测试环境且明确使用测试包集合时才允许模拟目录同步能力。

关闭标准：负向测试证明目录同步不支持时不签名、不发布、不留下 committed set；在目标卷上通过进程崩溃、主机重启和可控断电等价试验，证明恢复器只会看见完整旧代或完整新代；若平台不支持目录同步，则实现带摘要和序号的双清单或写前日志，注入清单写入、改名、刷新和重放各阶段故障，证明不会接受半提交代际。

## 5. 本轮质量门禁

第一轮修复及提交不确定性补丁后，最终自动化质量门禁通过：77 个测试文件、828 项测试、21 项运行时测试、69 个迁移、工作进程构建、生产网页构建和两套静态检查均成功；代码检查为零错误、102 个既有警告。另对验证器、模型清单、受管运行时、传输期限、资源租约、执行器和工作进程执行了 7 文件 232 项定向回归，全部通过。

该结果只证明代码基线可构建和自动化回归通过，不关闭六包实跑、应用任务链、部署身份隔离、十八类故障注入、旧版本读取或第二轮审查。

第二轮审查期间又修复了 Windows 目录同步不支持仍签名证据，以及审批服务接受调用者自造身份对象两项问题。修复后全量测试为 77 个文件、830 项全部通过；验证器与审批服务定向回归为 2 个文件、60 项，类型检查和差异格式检查通过。真实环境阻塞仍未关闭，因此不得把这些自动化结果解释为候选就绪。
