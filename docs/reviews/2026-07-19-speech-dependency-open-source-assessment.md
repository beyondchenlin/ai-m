# 语音依赖开源复用评估

日期：2026-07-19  
状态：`DECISION_REQUIRED`  
范围：`tts-index2`、`tts-index2-8g`、`tts-omnivoice-longform-bf16`、`tts-omnivoice-clone-duration-bf16`

## 1. 结论

当前“六包共用一个 Python 解释器”的方案不可继续。IndexTTS2 与 OmniVoice 对 `transformers` 的强制版本区间没有交集，包管理器因 IndexTTS2 插件错误的无上界依赖声明而产生了伪兼容结果。

建议优先采用：保留单一对外 `127.0.0.1:8000` 端点，在其后按语音引擎使用锁定的隔离执行环境；IndexTTS2 侧优先直接复用官方实现并编写本项目自有适配层，不复制许可证缺失的第三方插件代码。该方案属于架构变化，必须先获得批准并修改“单个后端进程”的验收口径，不能静默实施。

如果产品要求“一个监听器、一个 Python 解释器、同时加载全部六包节点”不可变，则当前任务应保持阻塞；现有上游中没有找到许可证明确且已证明同时兼容 `transformers>=5.3.0` 的 IndexTTS2 插件。

## 4. 推荐架构的完整验收标准

只有以下条件全部满足，才能解除依赖阻塞：

1. 对外只有一个回环监听端点；客户端、应用工作进程和数据库配置不得按包切换地址。
2. IndexTTS2 与 OmniVoice 各自使用可复现的锁文件、独立 Python 环境和独立依赖摘要；任何共享本地包必须有明确版本与摘要。
3. 第三方代码、模型、权重和音频处理依赖均有许可证清单；IndexTTS2 公司规模阈值、用途限制、修改声明和再分发义务有书面结论。
4. 路由层只接受清单内包标识，不允许请求注入解释器路径、命令、环境变量、模型根或监听地址。
5. 单资源槽条件下，六包按固定顺序执行；任意时刻只有一个模型推理，进程、显存、文件、租约和数据库证据一致。
6. 每包结束后完成工件原子提交、连接关闭、执行环境终止或清理、显存释放和健康复探；下一包不能继承上包临时输入、输出或进程状态。
7. 对启动失败、节点缺失、依赖摘要漂移、超时、取消、请求已写出但响应丢失、子进程崩溃、路由进程崩溃和主机重启逐项注入故障；不重复提交、不伪成功、不泄漏资源。
8. IndexTTS2 适配层执行固定参考音频和固定随机种子回归，验证音频容器、采样率、声道、时长、非静音、摘要记录和人工音质门槛；束搜索与情绪控制不得因接口迁移静默降级。
9. OmniVoice 的长文本、克隆和定长能力分别验证；不得仅以节点成功注册替代真实音频结果。
10. 新旧路由和执行环境完成升级、降级与数据不变演练；旧版本读取新证据前必须先发布兼容过渡版本。
11. 六包来自同一新代际，从首包开始完整执行；本次失败运行及其他局部结果不得拼接为通过证据。
12. 两名不同认证主体完成供应链审批，独立规格审查和对抗性代码审查均无未关闭问题，最终全量质量门禁在候选摘要上重跑通过。

## 5. 决策输入

批准前必须由负责人明确回答：

- 是否允许把“单一后端”解释为单一对外端点加隔离执行环境，而不再要求单一 Python 解释器。
- 公司及关联方是否触发 IndexTTS2 许可证的收入或月活阈值。
- 是否允许以官方 IndexTTS2 实现替换许可证缺失的第三方插件实现，同时保持现有工作流包的外部语义。
- 若不允许上述变化，是否正式变更六包验收范围；否则 RW-02 保持阻塞。
